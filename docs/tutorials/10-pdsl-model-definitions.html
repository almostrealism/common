Tutorial 10: Writing Models in PDSL

Read the platform's model files, then write a small decoder of your own

Home All Tutorials

Overview

PDSL is the language in which the platform writes down what its models compute. This tutorial first reads three of the shipped model files, one construct at a time, and then builds a small decoder of your own, step by step, until it is a complete program that loads from a checkpoint. You'll learn how to:

  • Read a PDSL layer and follow the shape of the data through it
  • Recognize residual connections, side branches and gates
  • Repeat a layer once per layer of a checkpoint with stack
  • Write and build a complete model, and hand it to the Java generation loop

Prerequisites:

  • Understanding of PackedCollection (Tutorial 2)
  • Computation graphs (Tutorial 4)
  • Running ML models (Tutorial 5)

This page teaches; it does not define. The grammar, every built-in and the exact rules live in the PDSL Language Reference, and each step below links to the part of it that applies.

Step 1: What PDSL Is For

In this project Java is the orchestration language: it describes a computation graph, and the framework compiles that graph to native kernels (Tutorial 4). PDSL takes the description one step further. A .pdsl file states the structure of a model, stage by stage, and the interpreter turns it into the same Block and Model graphs a hand-written Java layer would produce. Because the file holds nothing but structure, its text can look like the picture of the data flow you would draw on a whiteboard. Weight loading, the embedding lookup, sampling and the generation loop stay in Java.

The shipped files live in engine/ml/src/main/resources/pdsl/. The three you will read are feed_forward.pdsl, attention.pdsl and transformer.pdsl, plus the whole-model file qwen3.pdsl.

Step 2: Reading a Layer

Start with the feed-forward network of a Llama or Qwen decoder, the swiglu_ffn layer of feed_forward.pdsl. The file's doc comment draws it like this:

[1, dim] token vector
  └─ rmsnorm(norm_weights, epsilon)                          [1, dim]
     ├─ gate: dense(w1) → silu()                             [1, hidden_dim]
     └─ up:   dense(w3)                                      [1, hidden_dim]
     product(gate, up)   (element-wise, one multiply)        [1, hidden_dim]
  └─ dense(w2)                                               [1, dim]

and the layer itself is six lines of body:

layer swiglu_ffn(norm_weights: weight, w1: weight, w2: weight, w3: weight, epsilon: float) {
    rmsnorm(norm_weights, epsilon)
    product(
        { dense(w1); silu() },
        { dense(w3) }
    )
    dense(w2)
}

Read it top to bottom. Each line is a stage, and the output of one stage is the input of the next.

  • layer swiglu_ffn(...) declares a layer and its parameters. A weight is a tensor (a PackedCollection) and a float is a number used while the graph is being built.
  • rmsnorm(norm_weights, epsilon) normalizes the incoming vector and scales it by learned weights. The shape does not change.
  • product({ ... }, { ... }) runs two inline blocks on the same input and multiplies their outputs element-wise. Here that is the SwiGLU gate: one path is dense(w1) then silu(), the other is dense(w3). Inside braces, ; separates stages written on one line.
  • dense(w2) projects the gated hidden vector back to [1, dim].

The text is the picture: one line per box, and the two branches of the picture are the two arguments of product. The file's second layer, glu_feed_forward, is a variant that takes its projections as arguments; you can leave it for later. For the formal meaning of each statement, see Statements and their block semantics.

Step 3: Reading Attention

Attention is the larger read. attention.pdsl handles one token per forward pass: the input is that token's [1, dim] vector, and position is its index in the sequence. Keys and values of every earlier token are kept in a key/value cache, so each pass only has to compute the new token's key and value.

The score stage: attend

layer attend(heads: int, head_size: int, position: scalar,
             key_cache: weight, value_cache: weight) -> [heads, head_size] {
    attention_scores(key_cache)
    scale(1 / sqrt(head_size))
    causal_mask(position)
    softmax()
    weighted_values(value_cache)
}
  • attention_scores(key_cache) takes the query, one row per head, and scores it against every cached key: [heads, head_size] becomes [heads, seq_len].
  • scale(1 / sqrt(head_size)) is the usual 1/√d scaling. The argument is ordinary arithmetic, evaluated once while the layer is built.
  • causal_mask(position) penalizes every cached row after the current position, so a token cannot attend to the future.
  • softmax() turns each head's scores into weights.
  • weighted_values(value_cache) sums the cached values by those weights and returns [1, heads * head_size].

The arrow is not a return type. -> [heads, head_size] looks like an output shape, but it declares the input shape attend is built for when another layer calls it. Its doc comment gives the mapping as [heads, head_size] -> [1, heads * head_size]: the annotation names the left-hand side. When Java builds a layer directly, the annotation is not used at all; see The shape annotation in the reference.

The whole stage: attention

layer attention(heads: int, kv_heads: int, head_size: int,
                rms_att_weight: weight,
                wq: weight, wk: weight, wv: weight, wo: weight,
                bq: weight, bk: weight, bv: weight,
                freq_cis: weight, position: scalar, epsilon: float,
                key_cache: weight, value_cache: weight) -> [1, heads * head_size] {
    rmsnorm(rms_att_weight, epsilon)

    branch keys {
        dense(wk, bk)
        rotate_heads(kv_heads, head_size, freq_cis, position)
        repeat_each(heads / kv_heads)
        cache_write(key_cache, position)
    }
    branch values {
        dense(wv, bv)
        reshape([kv_heads, head_size])
        repeat_each(heads / kv_heads)
        cache_write(value_cache, position)
    }

    dense(wq, bq)
    rotate_heads(heads, head_size, freq_cis, position)
    attend(heads, head_size, position, key_cache, value_cache)
    dense(wo)
    reshape([1, heads * head_size])
}

Here the annotation -> [1, heads * head_size] is again the input shape: the [1, dim] token vector. Reading the body:

  • rmsnorm normalizes the token vector first (pre-norm).
  • branch keys { } is a side path. It receives the normalized vector, and the main path continues with that same vector; the branch's result is not passed on. The keys branch projects (dense(wk, bk)), applies rotary position embedding (rotate_heads, itself a layer of this file), duplicates each key head for the query heads that share it (repeat_each(heads / kv_heads), which is grouped-query attention), and writes the result into row position of the cache with cache_write.
  • branch values { } does the same for values, without rotation.
  • A branch runs before the path that follows it, so when the query path (dense(wq, bq), rotate_heads) reaches attend, both caches already hold the current token.
  • dense(wo) is the output projection, and the final reshape restores the [1, dim] layout.

bq, bk and bv are optional: a model without projection biases passes null and dense adds nothing.

By contrast, sdpa.pdsl scores a whole sequence at once with scaled_dot_product and a key_mask; it has no rotary embedding and no cache. It is a different kind of attention, not a variant of this one.

Step 4: Composing Layers into a Model

transformer.pdsl assembles attention and the feed-forward network into one pre-norm decoder layer. It does not redefine them; it imports the files that do:

import "/pdsl/attention.pdsl"
import "/pdsl/feed_forward.pdsl"
...
layer transformer(heads: int, kv_heads: int, head_size: int,
                  rms_att_weight: weight,
                  wq: weight, wk: weight, wv: weight, wo: weight,
                  bq: weight, bk: weight, bv: weight,
                  freq_cis: weight, position: scalar,
                  rms_ffn_weight: weight, w1: weight, w2: weight, w3: weight,
                  epsilon: float, key_cache: weight, value_cache: weight)
        -> [1, heads * head_size] {
    // Residual self-attention: the stream plus attention over its normalized copy.
    accum {
        attention(heads, kv_heads, head_size, rms_att_weight, wq, wk, wv, wo,
                  bq, bk, bv, freq_cis, position, epsilon, key_cache, value_cache)
    }

    // Residual feed-forward: the stream plus the SwiGLU network over its normalized copy.
    accum {
        swiglu_ffn(rms_ffn_weight, w1, w2, w3, epsilon)
    }
}
  • import "/pdsl/..." brings in every definition of another asset. Imports come before every definition and name a classpath resource.
  • accum { body } is a residual connection: the body's output is added to the input it read, so x becomes x + attention(x), then x + swiglu_ffn(x). The stream itself is never normalized in place; each stage normalizes its own copy.
  • A call such as attention(...) builds another layer of the program, passing arguments by position.

transformer.pdsl describes one layer. The repetition over layers lives in the whole-model files, qwen2.pdsl and qwen3.pdsl:

import "/pdsl/transformer.pdsl"

model qwen3(settings: model_settings, weights: checkpoint, position: scalar) {
    let rope = rope_freqs(settings.rope_theta, settings.dim / settings.heads, settings.seq_len)

    stack weights.model.layers as block {
        transformer_qk_norm(settings.heads, settings.kv_heads, settings.dim / settings.heads,
                            block.input_layernorm.weight,
                            ...
                            zeros([settings.seq_len, settings.dim]), zeros([settings.seq_len, settings.dim]))
    }

    rmsnorm(weights.model.norm.weight, 1e-6)
    dense(weights.model.embed_tokens.weight)
}
  • model declares a whole model rather than a layer.
  • weights: checkpoint receives the checkpoint. A dotted path such as weights.model.norm.weight names one tensor by its checkpoint key, and weights.model.layers names the group of everything under that prefix.
  • stack weights.model.layers as block { } repeats its body once per member of the group (model.layers.0, model.layers.1, ...), with block bound to that member. There is no index to compute keys from; each layer's weights are read as block.self_attn.q_proj.weight and so on.
  • let rope = ... binds a value for the rest of the body, here the rotary frequency table every layer shares. zeros([...]) allocates a fresh cache for each layer.
  • After the stack, a final rmsnorm and a dense onto the vocabulary give one score per token of the vocabulary.

The elided lines pass each weight of the layer as its own argument, twenty-two of them in all. Read that call to see which checkpoint tensor feeds which parameter; it is not a pattern to copy.

Why the residual lives in a layer. A model body accepts only expressions, let, for and stack. accum, branch and product are rejected there, so composition is written in a layer and the model calls it. The language also has an index loop, for i in 0..n { }; the platform's model files use stack instead, and so does this tutorial. See the statement table for both.

Step 5: Writing Your Own Decoder

Now write a small decoder of your own: two layers, each a residual attention stage and a residual gated MLP, then a vocabulary projection. It uses the constructs you have just read, simplified so the whole program fits on one screen: one key/value head per query head and no rotary embedding. Every program below is parsed by a test, and the final one is built from a checkpoint.

5a. A gated MLP

Write the feed-forward stage first. It is the shape of swiglu_ffn, with your own names and a fixed epsilon:

/** Pre-norm gated MLP: down(silu(gate(n)) * up(n)), where n = rmsnorm(x). */
layer gated_mlp(norm: weight, gate: weight, up: weight, down: weight) {
    rmsnorm(norm, 1e-6)
    product(
        { dense(gate); silu() },
        { dense(up) }
    )
    dense(down)
}

With norm [4], gate and up [8, 4] and down [4, 8], it maps [1, 4] to [1, 4]. A dense weight is [out, in].

5b. Attention over a cache

Next, attention. Two branches write the new token's key and value into the caches, and the query path scores against them. Instead of a separate attend layer, the score stages are written inline, after a reshape that splits the query into heads:

/** Single-token attention over a key/value cache, [1, heads * head_size] in and out. */
layer cached_attention(heads: int, head_size: int, norm: weight,
                       wq: weight, wk: weight, wv: weight, wo: weight,
                       position: scalar, key_cache: weight, value_cache: weight)
        -> [1, heads * head_size] {
    rmsnorm(norm, 1e-6)

    branch keys {
        dense(wk)
        cache_write(key_cache, position)
    }
    branch values {
        dense(wv)
        cache_write(value_cache, position)
    }

    dense(wq)
    reshape([heads, head_size])
    attention_scores(key_cache)
    scale(1 / sqrt(head_size))
    causal_mask(position)
    softmax()
    weighted_values(value_cache)
    dense(wo)
}

Follow the shapes for heads = 2, head_size = 2 and caches of [8, 4] (eight positions):

rmsnorm                      [1, 4]
keys:   dense(wk)            [1, 4]   cache_write → key_cache[position]
values: dense(wv)            [1, 4]   cache_write → value_cache[position]
dense(wq)                    [1, 4]
reshape                      [2, 2]   one row per head
attention_scores             [2, 8]   one score per head and cached position
scale, causal_mask, softmax  [2, 8]
weighted_values              [1, 4]
dense(wo)                    [1, 4]

The annotation -> [1, heads * head_size] says what this layer expects to be fed when another layer calls it, which is the token vector. It is not the output shape, even though here the two happen to agree.

5c. The decoder layer

Compose the two stages with residual connections, exactly as transformer does:

/** Pre-norm decoder layer: x + cached_attention(x), then x + gated_mlp(x). */
layer decoder_layer(heads: int, head_size: int, position: scalar,
                    attn_norm: weight, wq: weight, wk: weight, wv: weight, wo: weight,
                    mlp_norm: weight, gate: weight, up: weight, down: weight,
                    key_cache: weight, value_cache: weight) {
    accum {
        cached_attention(heads, head_size, attn_norm, wq, wk, wv, wo,
                         position, key_cache, value_cache)
    }
    accum {
        gated_mlp(mlp_norm, gate, up, down)
    }
}

This parses on its own, but it cannot be built on its own: it calls two layers it does not define. The next step puts all three in one program.

5d. The model

Finally, the model. It stacks decoder_layer over the checkpoint's layers group, gives each layer its own caches with zeros, and ends in a norm and the vocabulary projection. Here is the complete program, with the three layers you wrote above:

/** Pre-norm gated MLP: down(silu(gate(n)) * up(n)), where n = rmsnorm(x). */
layer gated_mlp(norm: weight, gate: weight, up: weight, down: weight) {
    rmsnorm(norm, 1e-6)
    product(
        { dense(gate); silu() },
        { dense(up) }
    )
    dense(down)
}

/** Single-token attention over a key/value cache, [1, heads * head_size] in and out. */
layer cached_attention(heads: int, head_size: int, norm: weight,
                       wq: weight, wk: weight, wv: weight, wo: weight,
                       position: scalar, key_cache: weight, value_cache: weight)
        -> [1, heads * head_size] {
    rmsnorm(norm, 1e-6)

    branch keys {
        dense(wk)
        cache_write(key_cache, position)
    }
    branch values {
        dense(wv)
        cache_write(value_cache, position)
    }

    dense(wq)
    reshape([heads, head_size])
    attention_scores(key_cache)
    scale(1 / sqrt(head_size))
    causal_mask(position)
    softmax()
    weighted_values(value_cache)
    dense(wo)
}

/** Pre-norm decoder layer: x + cached_attention(x), then x + gated_mlp(x). */
layer decoder_layer(heads: int, head_size: int, position: scalar,
                    attn_norm: weight, wq: weight, wk: weight, wv: weight, wo: weight,
                    mlp_norm: weight, gate: weight, up: weight, down: weight,
                    key_cache: weight, value_cache: weight) {
    accum {
        cached_attention(heads, head_size, attn_norm, wq, wk, wv, wo,
                         position, key_cache, value_cache)
    }
    accum {
        gated_mlp(mlp_norm, gate, up, down)
    }
}

/** A toy decoder: one decoder_layer per checkpoint layer, then one score per vocabulary entry. */
model toy_decoder(settings: model_settings, weights: checkpoint, position: scalar) {
    stack weights.layers as block {
        decoder_layer(settings.heads, settings.dim / settings.heads, position,
                      block.attn_norm.weight,
                      block.attn.q.weight, block.attn.k.weight,
                      block.attn.v.weight, block.attn.o.weight,
                      block.mlp_norm.weight,
                      block.mlp.gate.weight, block.mlp.up.weight, block.mlp.down.weight,
                      zeros([settings.seq_len, settings.dim]),
                      zeros([settings.seq_len, settings.dim]))
    }

    rmsnorm(weights.norm.weight, 1e-6)
    dense(weights.lm_head.weight)
}

The program reads these checkpoint keys, for each layer N:

layers.N.attn_norm.weight                       [dim]
layers.N.attn.q.weight  ... attn.o.weight       [dim, dim]
layers.N.mlp_norm.weight                        [dim]
layers.N.mlp.gate.weight, layers.N.mlp.up.weight  [hidden, dim]
layers.N.mlp.down.weight                        [dim, hidden]
norm.weight                                     [dim]
lm_head.weight                                  [vocab, dim]

Built for [1, 4] with dim = 4, heads = 2, seq_len = 8, a two-layer checkpoint, hidden = 8 and vocab = 16, the model has four blocks (two decoder layers, the norm and the projection) and outputs [1, 16]: one score per vocabulary entry. The program is self-contained on purpose. It has no import, because only classpath loading resolves imports (see Step 6).

Step 6: Running It from Java

Save the program as toy_decoder.pdsl, then parse and build it:

import org.almostrealism.ml.StateDictionary;
import org.almostrealism.dsl.PdslLoader;
import org.almostrealism.dsl.PdslNode;
import org.almostrealism.model.CompiledModel;
import org.almostrealism.model.Model;

PdslLoader loader = new PdslLoader();
PdslNode.Program program = loader.parse(Path.of("toy_decoder.pdsl"));

StateDictionary weights = new StateDictionary(weightsDirectory);   // the checkpoint
PackedCollection position = new PackedCollection(1);               // updated every step

Map<String, Object> settings = new HashMap<>();
settings.put("dim", 4);
settings.put("heads", 2);
settings.put("seq_len", 8);

Map<String, Object> args = new HashMap<>();
args.put("settings", settings);
args.put("position", position);

Model model = loader.buildModel(program, "toy_decoder", shape(1, 4), weights, args);
CompiledModel compiled = model.compile(false);
  • buildModel(program, name, inputShape, stateDict, extraArgs) binds the StateDictionary to every parameter typed checkpoint; every other parameter is taken from extraArgs by name.
  • parse(Path) and parse(String) read one source and do not resolve import. For a classpath asset that imports others, use loader.parseResource("/pdsl/transformer.pdsl"), which merges every imported definition into one program.
  • For a quick experiment without a checkpoint on disk, build a StateDictionary from a Map<String, PackedCollection> holding the keys listed above.

The model starts from a token's embedding and ends with scores, so the embedding lookup, the generation loop and sampling stay in Java, exactly as in the real models. AutoregressiveModel.of(compiled, position, token -> ...) wraps the compiled model with an embedding function and advances position each step; its subclasses KeyValueCacheAutoregressiveModel and SlidingWindowAutoregressiveModel are the other generators (Tutorial 5).

Common First Mistakes

These are the errors new PDSL authors meet most often, with what you will actually see. The complete list of messages is under Errors and diagnostics.

A shape that does not fit

Symptom: a dense weight whose second axis is not the input width, or an accum body whose output size differs from its input, fails with an IllegalArgumentException that has no message. Built-ins that check their input say so, for example softmax() expects a [rows, size] input shape, got [4].

Fix: write the shape next to each stage, as the asset doc comments do, and check that every dense weight is [out, in].

Reading -> [shape] as the output shape

Symptom: the layer builds fine from Java, because a direct build ignores the annotation, and then fails with a shape error from its first stage once another layer calls it, since the call builds it for the shape you wrote.

Fix: the annotation is the shape the layer is fed. Write the input shape, or leave the annotation out and let a call build the layer for whatever reaches it.

Forgetting a norm

Symptom: nothing reports it. The model builds and runs and its output is simply wrong. In a pre-norm layer each residual stage starts with its own rmsnorm.

Fix: compare your stages with the asset's data-flow picture, line by line.

Putting accum in a model

Symptom: Unsupported statement in model body: AccumStatement.

Fix: move the composition into a layer and call it from the model, as decoder_layer does.

Expecting parse(String) to resolve an import

Symptom: the program parses, and the build fails with Unknown function 'attention' at line N.

Fix: load the asset with parseResource, or make the program self-contained, as toy_decoder is.

A misspelled checkpoint path

Symptom: No weight named '...' among N weights; the closest names are ..., at line L.

Fix: the message lists the nearest keys; paths follow the checkpoint's own key names, segment by segment.
