# Make the self-hosted language model write a readable sentence about itself

## Title

Close the degenerate greedy-generation gap in the self-hosted LM through recipe and scale, so
`CausalLanguageModelTest.trainOnDocumentation` generates a non-trivial continuation of a
documentation prompt.

## Category

**Proof of Value.** A known-failing acceptance test and a model that emits a single repeated byte
are exactly the concrete, falsifiable gaps this category exists to close.

## Motivation

The self-hosted language-model track is one honest step from its headline promise. The platform
already trains a byte-level decoder-only transformer on its own documentation, end to end, every
gradient through the normal graph machinery, with weights that round-trip through `StateDictionary`.
As recorded in `docs/internals/training-a-language-model.md`, the documented configuration **beats
its unigram baseline — 4.194 bits per byte against 4.912** over all 83 held-out windows, measured on
exactly the targets the baseline describes.

But the model has never written a readable sentence. `CausalLanguageModelTest.trainOnDocumentation`
greedily continues the prompt `"The computation graph is compiled to "` for 96 bytes, and the
continuation is **96 spaces** — a single repeated byte — in every run recorded. The test's
`assertNonTrivialGeneration` check (reproducible, more than one distinct byte, not the prompt
repeated) therefore fails, and it runs before the baseline assertion, so the test is red even though
the model clears the baseline.

The training doc names the cause honestly: *"Closing the remaining gap to the bigram and trigram
rates (and with it, presumably, the degenerate greedy continuation) is a question of recipe and
scale (batch size above 1, more steps or epochs, a larger context or depth) rather than of step
cost."* The headroom is real: an interpolated count-based bigram fitted to the training region
scores 3.78 bits per byte on the held-out targets and a trigram 3.07, so a byte-level model of this
corpus has a great deal of headroom; the documented run, at 4.19, uses only part of it.

This is the direct next step named by the previous planning cycle (2026-10-18, item 2 of "what comes
next"): *"Proof of value — non-degenerate generation, revisited with a now-trustworthy gradient."*
The prerequisite that cycle set — a trustworthy reference gradient — is now met: PR #675 fixed the
nondeterministic full-Jacobian weight gradient by declaring hoisted kernel-index variables as 64-bit
(`Expression.getDeclarationType`). The gate is open.

This milestone is the first readable artifact of the self-understanding goal — the software writing
a sentence about its own architecture. It is worth doing carefully and honestly.

## Why the gap is the model, not the generation path

The investigation that produced this plan established, from source and the existing tests, that the
degenerate continuation is a property of the **trained model**, not a defect in the decoder:

- `CausalLanguageModelTest.slidingWindowGenerationMatchesFullForward` already proves the
  `SlidingWindowAutoregressiveModel` decodes *exactly* the full-sequence forward pass: every greedily
  generated byte, including those after the window slides, is the most probable byte of the
  corresponding row of a separate forward pass, and greedy decoding is reproducible after a reset.
  The generation path is faithful.
- The documented run reaches a **training** loss of about 3.5 bits per byte (near the bigram rate)
  but a **held-out** loss of 4.19. A model that generalizes this weakly, asked to continue a prompt
  it never saw, collapses its argmax to the unconditional most-frequent byte — a space, by far the
  most common byte in the corpus, and the prompt's own trailing byte. That is the signature of
  limited capacity and coverage, consistent with "recipe and scale," not a wiring bug.

The implication for scope: **the honest fix is a better-generalizing model**, produced by legitimate
recipe/scale changes, decoded by the generator exactly as it already decodes. The fix is *not* to
change what the test decodes with (greedy) or what it asserts.

## Scope

Concrete, actionable items. Every training run below is on Metal (see Dependencies) with
`AR_LONG_TESTS=enabled` and `AR_HARDWARE_MEMORY_SCALE=6`, and every reported number is measured, not
estimated.

1. **Re-measure the documented configuration with the corrected reference gradient.** Run
   `trainOnDocumentation` as it stands today and record the held-out bits per byte and the greedy
   continuation. State up front and then verify the expectation that the 64-bit full-Jacobian fix
   moves the held-out number only marginally for this model: dense layers (the output projection and
   all QKV/feed-forward projections) already take the reduced-delta vector-Jacobian product, not the
   full Jacobian, so the output-projection full-Jacobian defect PR #675 fixed is no longer on the
   LM's training path. Confirm this by comparison rather than asserting it. This establishes the
   honest starting point for every change that follows.

2. **Diagnose the greedy collapse with evidence, not speculation.** Inspect the log-probability
   distribution the generator produces at the step right after the prompt's trailing space: how
   peaked it is, and how large the space's margin over the next byte is. Compare greedy continuation
   of an *in-distribution* prompt (a verbatim fragment of a training page) with the out-of-
   distribution documentation prompt, to confirm the collapse tracks generalization. Record the
   finding; do not theorize past it.

3. **Apply recipe and scale levers in a prioritized, measured order.** Each change is reported with
   its held-out bits per byte *and* its greedy continuation, so the effect on both the baseline
   margin and the degeneracy is visible:
   - **Recipe within the current capacity first** (cheapest): epochs, the learning-rate schedule,
     and training-window coverage (`TRAIN_WINDOWS`, the spanning stride). The doc already shows a
     peak rate of 3e-3 keeps improving where 1e-2 stalls; extend from there.
   - **Capacity next**: `DEPTH`, `DIM` (embed), `SEQ_LEN` (context), and feed-forward width, within
     the memory budget. The doc records that the gated feed-forward input projection's Jacobian grows
     with the square of the feed-forward width and is why the width is 128 rather than 256 — respect
     that ceiling and report device-memory headroom as capacity grows.
   - **Batch > 1 last, and only if it fits the scope.** Larger batches reduce the update noise the
     doc blames for the late-training swings, but batched `scaledDotProductAttention` was flagged by
     earlier cycles as a possible capability gap. If enabling batch > 1 is a narrow, local change,
     make it; if it turns out to require broad autodiff or attention work, **do not expand this
     plan** — record the finding and file it as its own follow-up, exactly as the matmul-VJP history
     warns against broad in-flight changes to this area.

4. **Turn the generation assertion green honestly, or stop at an evidenced finding.** Success is a
   model whose greedy continuation is reproducible, has more than one distinct byte, and is not the
   prompt repeated — with the baseline assertion still green. The following are explicitly **out of
   bounds** and would fail `test-integrity-check`:
   - weakening `assertNonTrivialGeneration` (e.g. switching the test's decoding from greedy to
     sampled, lowering the distinct-byte bar, or removing the prompt-repeat check);
   - raising `@TestDepth` past what CI runs, inflating the timeout, or shrinking the model dimensions
     or the held-out baseline to make either assertion pass;
   - removing the `TODO(review)` note by hiding the failure rather than fixing it.
   If honest effort within the memory and timeout budget cannot clear the greedy bar, the correct
   outcome is an evidenced finding — which levers were tried, their measured held-out loss and
   continuations, and the concrete next recipe — handed to a revised plan, **not** a green test.

5. **Update `docs/internals/training-a-language-model.md`** with the new run: the re-measured
   held-out loss, the recipe/scale that produced non-trivial generation, and the actual continuation
   text the platform wrote. Keep the page's honest, measured voice; if the bar was not cleared,
   record that too, with the evidence.

## Approach

- Follow the mandatory tool rules: `consult` first, recall branch memories, and use
  `ar-profile-analyzer` to read the generator's output distribution and any expensive kernel before
  theorizing (Rule 3b). The collapse diagnosis in scope item 2 is a "what does this computation
  actually produce" question, which is what the profiler answers directly.
- The configuration lives as constants in `CausalLanguageModelTest` (`SEQ_LEN`, `DIM`, `HEADS`,
  `DEPTH`, `FF_DIM`, `EPOCHS`, `TRAIN_WINDOWS`, `LEARNING_RATE`, `FINAL_LEARNING_RATE`). Changing
  these to a larger, better-generalizing recipe is editing the run, which is allowed; weakening what
  the test asserts is not. Keep the two straight at every step.
- Run only `trainOnDocumentation` (and the fast generation/gradient tests that guard the pieces) via
  the MCP test runner with an explicit timeout; never a module-wide run. Watch the ~21-minute run
  time against the test timeout as capacity grows, and raise capacity only as far as the run still
  fits honestly — never by inflating the timeout.
- Keep each run's log (held-out curve, final held-out loss, greedy continuation, generation
  bytes-per-second, UTF-8 validity) so the doc update is transcribed from measurement.
- Validate with the build validator (checkstyle, code_policy, test_timeouts, duplicate_code) and
  confirm `test-integrity-check` is clean before declaring done.

## Success Criteria

- `CausalLanguageModelTest.trainOnDocumentation` passes **both** assertions honestly on Metal: the
  greedy continuation is reproducible, non-trivial (more than one distinct byte, not the prompt
  repeated), and the all-window held-out loss still beats the unigram baseline — with no weakening of
  the test, the baseline, the dimensions, `@TestDepth`, or the timeout.
- The platform emits a reproducible, readable continuation of the documentation prompt, logged
  verbatim in `training-a-language-model.md`.
- `training-a-language-model.md` reflects the new run accurately (held-out loss, recipe/scale, the
  continuation text), keeping its measured voice.
- Build validator and `test-integrity-check` clean.
- **Acceptable honest alternative** if scale within the budget cannot clear the greedy bar: an
  evidenced finding in the doc (and a branch memory) naming every lever tried, its measured held-out
  loss and greedy continuation, and the concrete next recipe for a revised plan. A green test bought
  by weakening the assertion is not an acceptable outcome.

## Dependencies

- **Met:** a trustworthy reference gradient. PR #675 fixed the nondeterministic full-Jacobian weight
  gradient (64-bit hoisted kernel-index variables). The prior cycle named this as the prerequisite.
- **Machine:** the training run uses Metal and `AR_HARDWARE_MEMORY_SCALE=6` (about 16 GB); the
  documented run takes roughly 21 minutes on Apple silicon. The work therefore requires a macOS
  node. See `plan-20261019-194959-workstream.yaml`.

## Estimated Complexity

**Medium.** The generation path and the training infrastructure already exist and are tested; the
work is diagnosis plus a measured recipe/scale sweep, bounded by the ~21-minute training run and the
test timeout. The principal risk is whether capacity reachable within the memory and time budget
generalizes well enough to make greedy decoding non-trivial — which is precisely why the plan admits
an honest evidenced-finding outcome rather than requiring a green test at any cost.
